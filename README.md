# Гроші ОК: особисті фінанси

Мобільний вебзастосунок для обліку особистих фінансів: витрати й доходи, кілька рахунків у різних валютах, перекази з обміном за фактичним курсом, звіти й аналітика, голосове введення та імпорт SMS банку. Мова за замовчуванням українська, можна перемкнути на англійську. Тема темна.

> Простий консольний скрипт `groshi_ok.py` з першої версії лишився в репозиторії, але основний продукт тепер описаний нижче.

---

## 1. Аналіз (етап 1)

**Відеореференс не було прикріплено до запиту**, тож інтерфейс побудовано за детальним текстовим описом у ТЗ: п'ять розділів, помаранчевий для витрат, зелений для доходів, синій для навігації, рожевий для балансів, вкладки «Рахунки / Перекази / Архів». Те, чого не було в описі, вирішено так:

| Неоднозначність | Рішення |
|---|---|
| Як підтверджувати витрату | Сума → рахунок → натискання категорії відкриває аркуш підтвердження (коментар, проєкт, дата, фото чека) → «Зберегти». Останній вибраний рахунок запам'ятовується. |
| Що відбувається з курсом, якщо ввести суму зарахування | Курс обчислюється з двох сум і зберігається. Обидві суми вважаються достовірними саме в тому вигляді, як їх ввів користувач. |
| Напрям курсу | Зберігається у форматі «1 база = курс котирування». За замовчуванням база — не гривня (USD/UAH), напрям можна перемкнути. |
| Видалення | М'яке видалення з журналом змін. Операцію можна відновити. |
| Коригування балансу | Різниця записується окремою операцією «Коригування». Це не дохід і не витрата, тому вона не потрапляє у звіти. |
| Архівна категорія | Лишається в історії та звітах. Категорію з операціями неможливо видалити: її буде архівовано. |
| Переказ в архівований рахунок | Заборонено. Баланс архівованого рахунку зберігається. |

## 2. Архітектура (етап 2)

```
web/     React 18 + TypeScript + Vite. SPA, PWA-маніфест (share target для Android)
server/  Node 22 + Express + TypeScript + zod
  src/engine/   фінансовий рушій без залежності від UI та БД:
                money.ts  (BigInt-копійки + decimal.js для курсів)
                rates.ts  (пошук курсу на дату, обернені й крос-курси)
                parser.ts (розбір голосових фраз і SMS)
  src/services/ ledger.ts (усі грошові операції, кожна в одній БД-транзакції + аудит)
                reports.ts (стрічка, звіти), catalog.ts (категорії, курси, імпорт, експорт)
  migrations/   SQL-схема PostgreSQL
```

**Гроші ніколи не зберігаються у float.** Суми лежать у `BIGINT` в мінімальних одиницях (копійки, центи) у валюті рахунку, курси — у `NUMERIC(20,10)`. Сервер передає суми десятковими рядками.

**Баланс рахуються з журналу, а не зберігаються окремим полем.** Їх обчислює SQL-представлення `account_balances`:

```
баланс = початковий + доходи − витрати + вхідні перекази − вихідні перекази + коригування
```

Тому баланс не може «роз'їхатися» з операціями.

**Перекази.** Один запис у таблиці `transfers` і дві пов'язані ноги в `transactions` (`transfer_out` і `transfer_in`). Створення, редагування та видалення атомарні: блокуються обидва рахунки, а все змінюється в одній транзакції PostgreSQL. Перекази й коригування ніколи не рахуються доходами чи витратами.

**Курси та валюти.**
- Історія курсів лежить у таблиці `exchange_rates`: дата, пара, курс, джерело (`manual`, `imported`, `transfer`).
- Базова валюта налаштовується, за замовчуванням UAH.
- Загальний капітал перераховується за останнім курсом на дату. Валюта без курсу **не додається** до суми, а показується попередження.
- У звітах кожна операція конвертується за курсом **на свою дату** (історична вартість). Нові курси не змінюють минулі звіти, а самі суми операцій не змінюються ніколи.

**Цілісність даних.**
- Обмеження `CHECK` і тригери в БД: валюта операції збігається з валютою рахунку; тип категорії збігається з типом операції; ноги переказу пов'язані.
- Валюту рахунку неможливо змінити, якщо на ньому вже є операції.
- Таблиця `audit_log` зберігає стан «до» і «після» для кожної зміни.

**Безпека.**
- Пароль хешується через scrypt.
- Сесія: httpOnly-cookie, у БД зберігається тільки хеш токена.
- Захист від CSRF: мутації приймаються лише як JSON із заголовком `X-Requested-With`.
- Обмеження кількості спроб входу, перевірка всіх вхідних даних через zod, заголовки безпеки.

### Таблиці БД
`users`, `sessions`, `settings`, `currencies`, `accounts`, `categories`, `projects`, `transactions`, `transfers`, `exchange_rates`, `attachments` (фото чеків у `bytea`, до 8 МБ), `imported_messages`, `audit_log`, представлення `account_balances`. Повна схема: [`server/migrations/001_init.sql`](server/migrations/001_init.sql).

| Метод | Шлях | Призначення |
|---|---|---|
| GET/POST | `/auth/me`, `/auth/register`, `/auth/login`, `/auth/logout`, `/auth/password` | Авторизація (перший користувач — власник) |
| GET/PUT | `/settings`, GET `/currencies` | Базова валюта, мова, часовий пояс |

| GET | `/export/json`, `/export/csv`, `/audit` | Резервна копія, експорт, журнал |

## 3. Функціонал (етап 3)

- **Витрати / Доходи.** Велике поле суми, цифрова клавіатура (на десктопі працює й фізична), рахунки з балансами (обраний підсвічується помаранчевим або зеленим), сітка категорій, суми за сьогодні, вчора, цей і минулий місяць, останні операції. Будь-яку операцію можна редагувати, видалити, продублювати чи прикріпити до неї фото чека.
- **Рахунки.** Вкладки «Рахунки / Перекази / Архів»:
  - загальний капітал у базовій валюті з розбивкою за валютами;
  - типи рахунків: готівка, банк, картка, заощадження, борг, інше;
  - початковий баланс, коригування, архівація, історія операцій.
- **Перекази.** З рахунку на рахунок. Для обміну вводиться курс (сума зарахування рахується сама) або фактична сума зарахування (тоді обчислюється курс). Для однакових валют курс завжди 1.
- **Стрічка.** Усі операції за днями з денними сумами. Фільтри: тип, рахунок, категорія (разом із підкатегоріями), проєкт, валюта, період. Пошук за сумою, категорією, рахунком і коментарем.
- **Звіти.** Періоди: день, місяць, рік або довільний.
  - Кільцева діаграма за категоріями: натискання відкриває операції цієї категорії; є перемикач на таблицю.
  - Динаміка, розбивка за рахунками й за проєктами чи джерелами, найбільші операції.
  - Порівняння з попереднім періодом, середнє на день, порівняння доходів і витрат за 12 місяців.
- **Категорії.** Необмежена кількість, іконка, колір, батьківська категорія, порядок, архів.
- **Проєкти / об'єкти.** Для витрат і доходів, з окремою історією.
- **Голосове введення.** Працює через Web Speech API (Chrome, Edge, Safari) або звичайним текстом.
  - Розпізнає тип, суму («1,250», «2 тисячі»), валюту, рахунок («моно», «приватом», «готівкою»), категорію та дату («вчора»).
  - Якщо чогось бракує або є неоднозначність, показує уточнювальні питання. **Кнопка підтвердження неактивна, доки не визначено суму, рахунок і категорію.**
- **Імпорт SMS.**
  - Вставте одне чи кілька повідомлень. Програма розпізнає суму, валюту, картку `*1234`, банк, дату, баланс і продавця.
  - Рахунок визначається за полем «Ознаки в SMS» рахунку.
  - Одне й те саме повідомлення двічі не імпортується. Схожа операція в межах ±36 годин позначається як «Можливий дублікат».
  - Баланс із SMS порівнюється з балансом у застосунку.
- **Налаштування.** Мова, базова валюта, часовий пояс, зміна пароля, експорт JSON (повна копія) і CSV (для Excel), журнал змін.

### Обмеження платформ (що свідомо *не* зроблено)
- **iOS не дає стороннім застосункам читати SMS**, і цю заборону ніяк не обходимо. Варіанти: скопіювати й вставити текст. На Android після «Додати на головний екран» застосунок з'являється в меню «Поділитися» (Web Share Target).
- **Голос.** Firefox не має розпізнавання мови, там лишається текстове поле.
- **Курси вводяться вручну.** Автоматичне завантаження з НБУ чи банку не підключене. Схема вже підтримує джерело `imported`, тож його легко додати.

## 4. Перевірка розрахунків (етап 4)

```bash
npm test     # 30 тестів: юніт-тести рушія + інтеграційні через HTTP на реальній PostgreSQL
```

Що перевіряють інтеграційні тести (`server/test/finance.test.ts`):
- витрата віднімає, дохід додає; `0,10 + 0,20 = 0,30` рівно; відхиляються від'ємні суми, понад 2 знаки після коми, чужі категорії;
- **$1 000 × 41,50 = 41 500 грн**: USD-рахунок −1000, UAH-рахунок +41 500, один запис переказу, курс збережено;
- обмін UAH→EUR за фактичною сумою зарахування (обчислений курс 45); переказ в одній валюті з курсом 1; переказ на той самий рахунок відхиляється;
- перекази **не потрапляють** у доходи й витрати;
- редагування переказу змінює обидва боки; невдала зміна нічого не змінює;
- редагування, видалення, відновлення й дублювання операцій перераховують баланс;
- видалення переказу повертає обидва баланси;
- коригування записується окремо й не впливає на звіти;
- загальний капітал: валюта без курсу виключається й позначається; після додавання курсу сума точна;
- історичні звіти не змінюються після появи нових курсів;
- архівна категорія лишається у звітах;
- відсотки, середнє на день, порівняння з попереднім періодом, пошук і фільтри;
- голос лише повертає чернетку; SMS: розбір, захист від повторного імпорту, пошук дублікатів;
- журнал змін, експорт JSON і CSV;
- **формула балансу перевіряється незалежним SQL-запитом для кожного рахунку.**

Додатково я перевірив усе в браузері (Playwright, iPhone 13 і десктоп): реєстрація, створення рахунків, витрати з клавіатури, дохід, переказ $1000 за 41,50 (попередній розрахунок показав 41 500,00), голосове підтвердження, стрічка, звіти, імпорт SMS. Помилок у консолі немає.

## 5. Встановлення

Потрібні Node.js 22+ і PostgreSQL 14+.

```bash
npm install
createuser -P finance && createdb -O finance finance        # або будь-яка інша база
cp server/.env.example server/.env                          # і вкажіть DATABASE_URL

# розробка (API :3000 + Vite :5173 з проксі /api)
export DATABASE_URL=postgres://finance:finance@localhost:5432/finance
npm run dev

# продакшн-збірка: один процес віддає і API, і вебзастосунок
npm run build
DATABASE_URL=... NODE_ENV=production npm start             # http://localhost:3000
```

Міграції застосовуються автоматично під час старту (або вручну: `npm run migrate`). Під час першого відкриття застосунок запропонує створити обліковий запис власника.

Для тестів потрібна окрема база, бо **тести очищують її схему**:
```bash
createdb -O finance finance_test
TEST_DATABASE_URL=postgres://finance:finance@localhost:5432/finance_test npm test
```

### Змінні середовища
| Змінна | Значення |
|---|---|
| `DATABASE_URL` | Рядок підключення до PostgreSQL |
| `PORT` | Порт HTTP, за замовчуванням 3000 |
| `NODE_ENV` | `production` вмикає Secure-cookie (потрібен HTTPS) |
| `APP_SECRET` | Ключ шифрування токенів банків/Telegram (обов'язково в продакшені) |
| `DISABLE_INTEGRATIONS` | `true` вимикає фонові Telegram-бот і синхронізацію monobank |
| `ALLOW_REGISTRATION` | `true`, щоб дозволити нових користувачів після першого (за замовчуванням вимкнено) |

## 6. Розгортання

```bash
DB_PASSWORD=надійний-пароль docker compose up -d --build   # PostgreSQL 16 + застосунок на :3000
```

Перед застосунком поставте HTTPS-проксі (Caddy, nginx, Cloudflare). Без HTTPS не працюють Secure-cookie, мікрофон і встановлення PWA. Підійде будь-який хостинг, де є Node і керований PostgreSQL (Render, Railway, Fly.io, VPS): команда збірки `npm ci && npm run build`, команда запуску `npm start`.

> Dockerfile і docker-compose написані за стандартним шаблоном, але в середовищі розробки їх не запускали, бо там не було Docker.

### Резервні копії
- `scripts/backup.sh [файл]` робить `pg_dump` у форматі custom. Відновлення: `pg_restore -d "$DATABASE_URL" --clean файл`.
- У застосунку: Меню → Налаштування → «Повна резервна копія (JSON)» або «Операції (CSV)».

## 7. Голосове керування, банки, Excel і фото чеків (версія 2)

### Голосове керування
Синя кнопка 🎤 є на кожному екрані (на «Витратах» і «Доходах» вона вгорі). Скажіть фразу або надрукуйте її:

| Фраза | Що станеться |
|---|---|
| «витратив 200 на таксі з моно», «зарплата 30000 на приват» | Відкривається заповнена форма, її потрібно підтвердити |
| «переведи 1000 доларів з Bank USD на Приват за курсом 41,5» | Відкривається заповнений переказ, його потрібно підтвердити |
| «скільки я витратив цього місяця», «скільки витратив на ресторани вчора» | Програма відповідає текстом і голосом, поруч кнопка «Показати операції» |
| «який баланс на моно», «баланс» | Відповідає балансом рахунку або загальним капіталом |
| «відкрий звіти», «покажи рахунки», «відкрий вхідні» | Переходить у потрібний розділ |

Розпізнавання мови працює через вбудоване в браузер (Chrome, Edge, Safari), а відповіді промовляються вголос (озвучення можна вимкнути). Записати операцію голосом без підтвердження неможливо.

### Як програма бачить витрати з банків
Усі операції з банків потрапляють у **Меню → Вхідні та імпорт → Вхідні**. Там кожну можна перевірити, підтвердити або пропустити, а кнопка «Підтвердити всі готові» записує ті, де все розпізнано й немає підозри на дублікат. Нове з'являється без участі користувача, а лічильник на кнопці «Меню» показує, скільки операцій чекає.

1. **Telegram-бот** (Меню → Підключення банків):
   - створіть бота в @BotFather, вставте токен у застосунок і натисніть посилання, щоб прив'язати свій чат;
   - пересилайте боту SMS чи сповіщення банку або пишіть «200 таксі моно». Бот покаже чернетку з кнопками вибору рахунку й категорії і кнопками «✅ Записати» / «✖️ Пропустити»;
   - фото чека з підписом «250 АТБ» створює операцію з прикріпленим чеком. Фото без підпису бот запропонує прикріпити до однієї з останніх операцій;
   - команди: `/balance`, `/today`, `/month`, `/inbox`. Можна ставити питання: «скільки я витратив цього місяця»;
   - бот отримує повідомлення сам (long polling), тому публічна адреса сервера не потрібна. Писати йому можуть лише прив'язані чати;
   - голосові повідомлення Telegram бот не розшифровує: для цього потрібен платний сервіс розпізнавання. Диктуйте текст мікрофоном на клавіатурі.
2. **monobank:**
   - особистий токен з api.monobank.ua; кожну картку треба зіставити з рахунком у тій самій валюті;
   - виписка підтягується кожні 10 хвилин або кнопкою «Синхронізувати зараз». Під час першого запуску програма бере останні 7 днів;
   - категорія визначається за MCC-кодом продавця (магазин, ресторан, таксі тощо);
   - перекази між власними картками позначаються підказкою, щоб не записати їх як витрату;
   - API monobank дозволяє 1 запит на хвилину на картку, тож картки синхронізуються по черзі.
3. **Пересилання SMS:** «Створити адресу» дає одноразово показану адресу `…/api/hooks/ingest/<токен>`.
   - **Android:** застосунок на кшталт «SMS Forwarder» пересилає SMS банку POST-запитом на цю адресу.
   - **iPhone:** Команди → Автоматизація → «Повідомлення» від банку → «Виконати одразу» → «Отримати вміст URL» (POST, JSON `{"text": Вміст повідомлення}`).
   - Сервер має бути доступний з інтернету (HTTPS).
4. **Вручну:** вкладка «Вставити SMS» або «Поділитися» на Android.

Токени Telegram і monobank зберігаються в базі зашифрованими (AES-256-GCM) і ніколи не повертаються через API. Адреса для пересилання SMS зберігається лише як хеш. **У продакшені задайте `APP_SECRET`** (довгий випадковий рядок). Без нього ключ шифрування створюється у файлі `.app-secret` у робочій папці.

### Excel
- **Експорт:** Звіти → «Експорт в Excel» за обраний період. Файл .xlsx містить аркуші «Підсумки» (разом, середнє, категорії з %), «Операції», «Рахунки», «Перекази». У Налаштуваннях можна експортувати всю історію.
- **Імпорт:** Вхідні та імпорт → Excel.
  - Можна завантажити шаблон або власну таблицю (.xlsx чи .csv) зі стовпцями Дата, Тип, Рахунок, Сума, Валюта, Категорія, Проєкт, Коментар.
  - Програма показує попередній перегляд з помилками й можливими дублікатами кожного рядка. Відсутні рахунки, категорії та проєкти створюються за згодою.
  - Усі коректні рядки записуються **однією транзакцією**: або всі, або жоден. Повторний імпорт того самого файлу пропускає дублікати.
  - Перекази й коригування з Excel не імпортуються.

### Фото й скріншоти чеків
У формі будь-якої витрати чи доходу є дві кнопки:
- **«Сфотографувати»** відкриває камеру;
- **«Скрін / файл»** відкриває галерею, скріншоти й PDF.

Вкладення показуються мініатюрами, відкриваються на весь екран і видаляються хрестиком. Великі фото стискаються до ~1600 px. Ліміт — 8 МБ на файл.
